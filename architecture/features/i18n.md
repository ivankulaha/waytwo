# Feature: Internationalization (mobile)

## Overview

The Expo app supports **English (`en`)** and **Ukrainian (`uk`)** for all user-visible strings in scoped areas (auth, home, tabs, modal, Explore template).

## Implementation

- **Config:** `mobile/lib/i18n.ts` — `i18next` + `initReactI18next`, resources from JSON, `react.useSuspense: false`.
- **Locale detection:** `expo-localization` — `uk` if device primary language code is `uk`, else `en`; fallback `en`.
- **Provider:** `I18nextProvider` wraps the app in `mobile/app/_layout.tsx` (outside `AuthProvider` so navigation and auth screens can call `useTranslation`).

## Catalogs

- `mobile/locales/en/common.json`
- `mobile/locales/uk/common.json`

Keys are grouped (`auth`, `validation`, `tabs`, `modal`, `home`, `explore`). Navigation titles use `t('tabs.home')`, etc.

## Validation

Zod helpers in `mobile/lib/validation.ts` take **translated** error messages from callers: `parseEmail(value, t('validation.invalidEmail'))`, `parsePassword(value, t('validation.minPassword12'))`.

## Adding a language

1. Add `mobile/locales/<code>/common.json`.
2. Register in `mobile/lib/i18n.ts` (`resources`, `supportedLngs`).
3. Extend `resolveInitialLanguage()` if the locale code should map differently.
